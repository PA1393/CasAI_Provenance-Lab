CasAI — active no-login demo release checklist
============================================

CURRENT LOCAL BEHAVIOR
- No login prompt when ACCESS_MODE=demo (the default).
- Shared, separately stored demo inputs/runs/folders; do not use private data.
- Existing personal/legacy data stays in its original tables and is not copied.
- Preserved optional account implementation and migration 008 for later.
- Explicit issue stage/code/explanation/next step on stopped runs and exports.
- Vault no-matches does not masquerade as a provider outage, or vice versa.
- Real no-edit outcomes do not become fabricated successful results.
- Exact workflow-completion statistics are not biological success percentages.
- Sources are preserved from the actual analysis result and shown from provenance.
- No external references are downloaded automatically.
- Connection indicator distinguishes explicitly reported temporary storage from
  a configured Supabase adapter; localhost alone does not imply temporary data.
  It checks API capabilities every 30 seconds, not database/scientific accuracy.
- All four result tabs wrap into a two-column layout on narrow screens.
- Score help explains GC/homopolymer scoring, zero values and sequence-only,
  PAM-agnostic off-target limitations without modifying the recorded scores.
- Browser exports say download requested, not saved; verified JSON is opened
  automatically as a fallback. Native confirmed writes remain distinct.
- Demo help includes a session-only reviewer checklist and feedback report.

DEPLOYMENT REQUIRED BEFORE DISTRIBUTION
1. Back up and review the staging schema. Ensure core migrations 001–007 have
   been applied. Apply 009_isolated_demo_and_run_issues.sql once. 008 is optional
   while accounts are deferred. 009 creates empty demo tables; it does not copy,
   publish or delete historical/personal rows.
2. Configure server-only SUPABASE_URL and SUPABASE_SERVICE_KEY, ACCESS_MODE=demo,
   explicit HTTPS CORS and a nonzero production rate limit.
3. Configure OPENAI_API_KEY/provider availability and reviewed vault content if
   assisted analysis is to be demonstrated. Without it, the rule-based modes
   remain usable; assisted runs explain the missing dependency.
4. Use persistent shared processor storage when the backend has multiple
   instances. Keep demo/ separate from users/ and from old shared artifacts.
5. Deploy the corresponding API and web client. Rebuild the desktop package for
   each OS; older downloaded installers do not pick up code changes themselves.

SCIENTIFIC/PRODUCTION LIMITS THAT REMAIN
This is a software demonstration, not yet an experimentally validated CRISPR
prediction product. Heuristic scores lack a calibrated accuracy percentage.
Interactive scenes do not compute validated molecular dynamics or enzyme paths.
Reference structures are deposited coordinates, not proof of an input-matched
editing interaction. External engines require installed tools, selected/licensed
references, explicit adapters and benchmarks before scientific accuracy claims.
No-login demo data is accessible to anyone with the endpoint; do not upload
confidential researcher data. Production multi-user privacy requires the saved
account feature plus independent deployment/security/storage verification.

  CASAI_DISPOSABLE_REHEARSAL=1 apps/api/.venv/bin/python test-fixtures/desktop-demo/rehearsal_server.py

Stop the fixture afterward. It rejects import/non-opt-in startup, binds only
loopback, uses RAM rows and temporary processor files, and disables hosted AI.
